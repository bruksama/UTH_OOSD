## Overview

Document the Codecept workflow and verify it runs in the real local stack. The lecturer-facing result is terminal Codecept output plus a local HTML report from `npm run test:codecept`.

## Requirements

- Functional: document required services and environment variables.
- Functional: document exact Codecept commands.
- Functional: document HTML report path.
- Functional: verify compile/build and Codecept run.
- Non-functional: no generated reports, screenshots, `.env`, or Firebase service files committed.

## Architecture

The test workflow remains manual-service-first:
1. `docker-compose up -d`
2. `cd backend && mvn spring-boot:run`
3. `cd frontend && npm run dev`
4. `cd frontend && CODECEPT_TEST_EMAIL=... CODECEPT_TEST_PASSWORD=... npm run test:codecept`
5. Open `frontend/output/report/testomatio-report.html`

This keeps Spring Boot lifecycle outside the JS test runner and makes demo failures easier to diagnose.

## Implementation Steps

1. Add Codecept E2E subsection to `docs/CONTRIB.md`.
2. List prerequisites:
   - database running,
   - backend running with Firebase configured,
   - frontend running,
   - `CODECEPT_TEST_EMAIL` and `CODECEPT_TEST_PASSWORD` set locally.
3. Add commands for headless and headed runs.
4. Document HTML report:
   - path: `frontend/output/report/testomatio-report.html`,
   - generated by `npm run test:codecept`,
   - ignored by git.
5. Add a short troubleshooting table:
   - login stuck,
   - 401 from `/api/auth/me`,
   - missing env var,
   - Vite/backend not running,
   - HTML report not generated.
6. Run verification:
   - `cd frontend && npm run build`
   - `cd frontend && npm run test:codecept`
   - `test -f frontend/output/report/testomatio-report.html`
7. Optional regression sanity:
   - `cd frontend && npm run test:e2e` only if time allows, to confirm Playwright still works.
8. Summarize output locations:
   - terminal output,
   - HTML report,
   - screenshots/failures under ignored `frontend/output/`.

## Risk Assessment

- Risk: local backend or Firebase token misconfigured. Mitigation: docs point to backend health and Firebase env checks.
- Risk: generated output gets staged. Mitigation: ignore `frontend/output/` and inspect `git status`.
- Risk: HTML report plugin fails silently. Mitigation: make report file existence a success criterion.
